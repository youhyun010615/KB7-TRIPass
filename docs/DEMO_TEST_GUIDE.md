## 3. 로컬에서 프론트엔드로 테스트하는 법

harness의 `.claude/launch.json` 프리셋(`tripass-frontend`)은 오래된 별도 클론을 가리키고 있어서 **쓰지 말 것**. 대신 아래처럼 직접 실행한다.

```bash
cd frontend
echo "VITE_API_BASE_URL=http://54.117.23.0:8080/api/v1" > .env.local
npm install
npm run dev -- --port 5174
```

- 포트는 반드시 `5173` 또는 `5174` 사용 (백엔드 CORS 허용 origin이 이 두 개뿐임 — `SecurityConfig.java`)
- 브라우저에서 `http://localhost:5174` 접속 → `yuhyun` / `Mock1234!` 로그인

## 4. 가상 날짜 전환 방법

앱 내: **마이페이지 → 맨 아래 "가상 날짜 설정 [DEV]" 패널**에서 날짜 입력 후 "적용" 클릭.

API 직접 호출:
```bash
curl -X POST "http://54.117.23.0:8080/api/v1/dev/override-date?date=2027-01-25" \
  -H "Authorization: Bearer $TOKEN"
```

날짜 해제(실제 날짜로 복귀):
```bash
curl -X DELETE "http://54.117.23.0:8080/api/v1/dev/override-date" \
  -H "Authorization: Bearer $TOKEN"
```

⚠️ **가상 날짜를 실제 오늘 날짜와 정확히 같은 값으로 설정하면 안 됨.** `devDateUtil.today()`가 `LocalDate.now()`와 같아지는 순간 월렛 잔액이 동적 계산(ledger 합산) 대신 시드 최종값(5,249,000원)을 그대로 보여줌. 반드시 실제 날짜와 다른 값으로 테스트할 것.

## 6. 데모 상태 자동 리셋 확인

여러 명이 같은 계정으로 QA할 때, 화면에서 직접 충전/환전/카드탑업 등을 실행하면 임시 기록이 남는다. **날짜를 다른 값으로 전환하는 순간 자동으로 삭제되고 시드 상태로 복원된다** (`DEMO-SEED-*` 태그가 없는 모든 wallet_ledger/환전/카드탑업 기록 삭제 후 잔액 재계산).

확인 방법:
1. 아무 날짜로 이동 (예: 10/26)
2. 화면에서 충전 실행 → 잔액 변화 확인
3. 다른 날짜로 이동했다가 다시 10/26으로 복귀
4. 잔액이 원래 시드값(1,659,000원)으로 돌아왔는지 확인

## 8. 참고 — DB 시드 재실행

seed 데이터가 꼬였을 때 (계정 데이터 초기화 버튼을 눌렀거나, DB가 초기화된 경우) GitHub Actions로 재실행 가능:

```bash
gh workflow run run-seed.yml --ref develop -f sql_file=demo_yuhyun_seed.sql
```

`demo_yuhyun_seed.sql`은 idempotent하게 작성돼 있어서 (기존 yuhyun 데이터 cleanup 후 재삽입) 여러 번 실행해도 안전함.
